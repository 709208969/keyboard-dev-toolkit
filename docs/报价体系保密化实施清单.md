### 4.2 `quote.ts` 计算规格（含 api 字段精确化）
移植 `price-calculator.ts` 全部规则，但**删除一切倍率运算**（表内数值已消融）：
- `calculatePrice` 核心：板材费/工艺费/固定成本/贴片/钢网/快递（公式见 `计价方式.md` §3，逐条移植：0.8 系数、辅助边 5mm、间隙 1.6mm、张数上取整、N≤0 拒绝、超限拒绝、沉金公式、颜色单价、贴片门槛按下单数量、快递轻/重货公式与无上限、v2.6.0 附加组件与"仅提示不阻断"）。
- **语义唯一化（防口径漂移，覆盖旧代码的全部"数量"概念）**：
  - `quantity`（请求）= 客户下单数 N；
  - `deliveryQty` = N（输出直接回传 N，客户端展示"交付数量 N PCS"）；
  - `effectiveQty`（=ceil(N/5)*5）与 `wasteQty` = effectiveQty - N 为**引擎内部量**：张数(板材需求)按 effectiveQty 计算，但**两者绝不输出**；单价分母用 `deliveryQty`（=N）；
  - ⚠ 旧引擎 `unitPrice = totalPrice ÷ effectiveQty` —— 新引擎改为 `÷ deliveryQty(=N)`，与旧引擎**不等价**：附录 E 对账案例须**仅对 totalPrice 做等价断言**（unitPrice 断言 = 新表自身一致性：`format(totalPrice/deliveryQty)` 复用同一除数，不许用旧值）；在验证报告"不一致项"中显式记录"单价分母 N vs effectiveQty 的差异属于用户决策（客户只看见 N）"。
- `calculatePlateQuote`：定位板（复用 PCB 板材逻辑、加工费 `max(张数×费率, 750)`【注：750 = 旧 300×2.5，生成器已换算，此处直接用表值】、totalPrice 等价断言见 4.3）。
- **应用分档**：`tiers` 为空数组时整段跳过（默认）；非空时 `totalPrice = totalPrice × 档位因子`（当前阶段强制 `tiers=[]`，**禁止实现任何"默认档位/默认 0.95 之类"的补偿性数值**）。
- 输出（**精确定义，只许这些字段**）：
  ```
  { ok: true,
    totalPrice: number,        // 人民币终端总价（精确小数）
    unitPrice: number,         // = totalPrice / deliveryQty（保留原始精度）
    deliveryQty: number,       // = 请求 quantity（=N）
    sheets: number,            // 用板张数（仅整数参考值，内部按 effectiveQty 计算张数）
    notice?: string,           // 原引擎 notice（若原文案涉及"报废/每张块数/模式"字样 → 改写为不含内部量的表述或删除）
    version: string }          // metaVersion
  或 { ok: false, reason: string }
  ```
  ⚠ **禁止输出**：mode、boardsPerSheet、wasteQty、chargeSizeMm、effectiveQty、任何成本字段、倍率。
- `POST /api/quote` 请求体字段（与 `PricingFormData` 完全同名，附录 D）：全部为表单 JSON；`validatePricingInput` 校验逻辑保留（错误返回 `{ok:false, reason}` 用现有拒绝文案常量）。
- 定位板并入同一请求：若 `plateQuantity>0`，响应增加 `plate?: { ok,totalPrice,unitPrice,deliveryQty,sheets,reason? }` 字段（同规格）。
- `GET /api/meta` 响应（**不含任何价格字段**，只含 名称/排序/reject 标记/sortOrder/contacts/version/updatedAt）：
  ```
  { version, updatedAt,
    materials: [{key,name,sortOrder}],
    surfaceFinish: [{key,name,sortOrder,reject?,rejectReason?}],
    solderColors: [{key,name,sortOrder}],
    options: {
      // ⚠ encoder 与 oled 是【单项对象】不是数组（与旧 UI cfg.options.encoder.name 用法保持一致）：
      encoder: { name, reject? },        // 单项
      oled: { name, reject? },           // 单项
      communication: [...], solder: [...], logo: [...], protection: [...], test: [...], packaging: [...]
    },
    extras: { subBoard:[...], cable:[...], firmware:[...], tracing:[...] },
    plateMaterials: [{key,name}],
    contacts: { discord?, email? } }
  ```
  修正说明：**全部列表项只含白名单字段（key/name/sortOrder/reject/rejectReason），encoder/oled 为单项对象——执行代理若将 encoder/oled 实现为数组 = 直接失败**。此响应由 meta.ts 显式挑选构建，禁止"复制整个对象再删字段"的偷懒法。
- 所有路由设置 CORS：`Access-Control-Allow-Origin: *`、`Access-Control-Allow-Methods: GET,POST,OPTIONS`，处理 OPTIONS 预检（返回 204）。
